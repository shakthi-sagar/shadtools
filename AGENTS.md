# ShadTools AI Agent Guidelines & Operating Rules

This document provides strict instructions, architectural constraints, and engineering guardrails for AI coding assistants working in the `shadtools` repository.

---

## 🚨 MANDATORY AGENT DIRECTIVES

### 1. `@/*` Import Path Aliases
- **ALWAYS** use `@/*` for imports mapping to `src/*`.
  - ✅ `import { Button } from '@/components/ui/Button'`
  - ❌ `import { Button } from '../../components/ui/Button'`
- If relative imports are generated by any scaffolding script, immediately run `npx tsx scripts/convert-relative-imports.ts` to convert them to `@/` aliases.

### 2. Component Reuse over Duplication
- **DO NOT** re-implement raw `<textarea>` inputs or pane headers inside individual tool components.
- Use shared components from `@/components/tool-ui/`:
  - `CodeEditorPane`: Dual-pane and single-pane code/text editor panels.
  - `ToolFrame`: Outer container card for all tool workspaces.
  - `ResultPanel`: High-contrast calculation outputs.
  - `FileDropzone`: Client-side image and file upload dropzones.

### 3. Focus Ring & Outline Guidelines
- Textareas inside `CodeEditorPane` and code tools **MUST** use `outline-none ring-0 focus:outline-none focus:ring-0 focus:border-none shadow-none` so clicking an input never clips a bright blue ring outline into surrounding headers or card boundaries.

### 4. Unit Converter Layout Architecture
- Converter inputs (`Amount`, `From`, `To`) MUST sit in a 3-column `grid grid-cols-1 sm:grid-cols-3 gap-4 items-start` layout with equal `h-10` controls and top-aligned labels.
- The `Copy Result` button MUST sit inside the top header of the `CONVERTED RESULT` card alongside the formula disclosure line.

### 5. Quality & Verification Rules
Before declaring any task complete, run the following verification commands:
```bash
# 1. Registry & stale style validation
npm run validate

# 2. TypeScript diagnostics
npx tsc --noEmit

# 3. Vitest unit tests
npm run test

# 4. Static production build
npm run build
```
